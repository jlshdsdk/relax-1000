第 31 题
主机A 与主机B 的TCP 连接上，A 收到了一个来自B 的纯确认段（即有效载荷为0 字节）。该段的序号为1913，确认序号为2046。假设A 有数据要发送，则A 立即回应的TCP 段的序号和确认序号分别是（）。
  1. A．2046, 1913
  2. B．2047, 1913
  3. C．2046, 1914
  4. D．2047, 1914
答案与解析

答案：A

B 发来的报文段中确认序号为2046，这表示B 已经成功接收了A 发送的到2045为止的所有字节，并期望接收从2046 开始的字节，因此A 发送的新数据段序号应为2046。A 发送报文段的确认号(ack)则取决于A 对B 数据的接收情况。B 发来的报文段序号为1913，且是纯确认段，不消耗序号。这意味着B 上一个发送的字节序号是1912，A 仍在等待从B 接收序号为1913 的字节。因此， A 回应的确认号应为1913。

第 32 题
主机A 正在与主机B 进行TCP 通信。此时A 收到了一个来自B 的连接释放请求段（不携带数据）。该段的标志位FIN=1，序号为7700，确认序号为8800。则A 为响应此FIN 段而发送的确认段中，序列号和确认序号分别是（）。
  1. A．8800, 7700
  2. B．8801, 7700
  3. C．8800, 7701
  4. D．8801, 7701
答案与解析

答案：C

TCP的确认序号（ack）是期望收到对方下一个报文段的第一个数据字节的序号。主机A 收到B 发来的FIN 段，其序号（seq）为7700，由于FIN 标志位即使不携带数据也要消耗一个序号，因此A 在响应时发送的确认序号应为7700+1=7701。TCP 的序号（seq）是本报文段所发送的数据的第一个字节的序号。主机A 收到的报文段中确认序号为8800，这表明B 已经正确收到了A 发送的到8799 为止的所有字节，并期望下一个字节是8800。因此，A 发送的响应确认段的序号就应该是8800，故C 正确。

第 33 题
主机甲与主机乙建立TCP 连接，甲发出的第一个段是SYN 段，其序列号为x。乙收到后，向甲回送一个SYN-ACK 段。甲收到后再回送一个ACK 段（不附带数据），并紧接着发送一个包含100字节数据的段。这个数据段的序列号应该是（）。
  1. A．x
  2. B．x+1
  3. C．x+100
  4. D．x+101
答案与解析

答案：B

主机甲发出的第一个SYN 段，序列号为x，该SYN 段会消耗一个序号。因此，甲发送的下一个段的起始序号应为x+1。甲在收到乙的SYN-ACK 段后，回送的ACK 段（三次握手的第三个段），其序号为x+1。

第 34 题
主机A 与主机B 建立TCP 连接，A 发送的SYN 段序号为3000。在无任何重传的情况下，A向B 共发送了6000 字节的应用层数据。那么当A 发送FIN 段以关闭连接时，该FIN 段的序列号应为 （）。
  1. A．9000
  2. B．9001
  3. C．9002
  4. D．9003
答案与解析

答案：B

TCP 报文段的序号是该报文段所发送数据的第一个字节的序号。建立连接时，A发送的SYN段消耗一个序号。因此，A 发送的第一个数据字节的序号是3001。A 共发送了6000 字节的数据，这些数据的序号范围是[3001, 3001+6000-1]，即[3001, 9000]。当所有数据都发送完毕后，A 的下一个可用序号是9001。FIN 段是在所有数据都发送完毕后才发送的，因此它将被赋予当前的下一个可用序号。所以，该FIN 段的序列号应为9001。

第 35 题
在TCP 协议里面，主机A 发送若干数据给数据B，那么下列说法错误的是（ ） I．若主机B 收到两个相同的分组，那么直接丢弃晚来的分组即可II．A 收到正确的确认报文后，滑动窗口应该往后滑动III．A 的发送缓存一定是发送窗口的子集IV．B 的接收窗口一定是接收缓存的子集
  1. A．II、III
  2. B．I、II、III
  3. C．I、III、IV
  4. D．I、II、III、IV
答案与解析

答案：B

主机B 收到两个相同的分组，一定是B 的确定报文段丢失了，应该丢失晚到的报文段，然后再发一个确认，I 错误。若接收窗口变小，滑动窗口可能不变。总结如下： • 发送缓存：应用层想要发送的数据。缓存空间有限并且循环使用，逻辑上是一个圆。其中包含两个部分：
①发送方的应用程序传送给发送方TCP 准备发送的数据。
②TCP 已发送出但未收到确认的数据。 • 发送窗口：发送窗口里的序号表示允许发送的序号。包含：①已经发送了的但是还未收到确认的②允许发送但是还未发送的。发送窗口左端点在收到新的确认后往右移动，没收到确认则不动。发送窗口右端点通常是不断往右移动，因为收到了新的确认。但是也可能不动，因为接收发的接收窗口变小了，导致不动。但是TCP 标准不赞成往左移动，因为窗口里的数据大部分已经发送出去，现在又要收缩窗口，不让发送这些数据，这样就会产生一些错误。 • 接收缓存：即将交给应用层的数据。包含：①按序到达的、但尚未交付应用进程的数据②未按序到达的 • 接收窗口：用来接收即将到达的数据，按序达到的数据，发送确认后接收窗口往右移动，但是不能超过接收缓存的范围。 • 发送窗口的序号集是发送缓存序号集的子集。 • 接收窗口的序号集是接收缓存序号集的子集。

第 36 题
主机A 和主机B 新建一个TCP 连接，MSS=1KB。连接建立后，A 的拥塞窗口cwnd 初始值为1KB，慢开始阈值ssthresh 为16KB。A 向B 发送一个最大段后，经过一个RTT 成功收到了确认，该确认段通告的rwnd 为1KB。此时A 的拥塞窗口cwnd 和发送窗口swnd 分别变为（ ）。
  1. A．2KB, 1KB
  2. B．1KB, 1KB
  3. C．2KB, 2KB
  4. D．1KB, 2KB
答案与解析

答案：A

TCP 的发送窗口swnd 的大小取决于拥塞窗口cwnd 和接收方通告窗口rwnd 的较小值，即swnd=min(cwnd, rwnd)。初始时，cwnd=1KB<ssthresh=16KB，TCP 处于慢开始阶段。在此阶段，每成功收到一个对新报文段的确认，拥塞窗口cwnd 就增加一个MSS的值。A 发送1KB（1个MSS ）并成功收到确认后，其cwnd变为2KB 。此时，A的发送窗口大小为swnd=min(cwnd, rwnd)=min(2KB, 1KB)=1KB。

第 37 题
下列关于TCP 拥塞控制的说法中，正确的是（ ）。
  1. A．发送方和接收方接收窗口的大小是一样的。
  2. B．TCP 的拥塞避免算法启动后，便可确保网络不再发生拥塞。
  3. C．快重传机制要求发送方一旦收到3 个冗余ACK 就立刻重传，且不允许使用捎带确认。
  4. D．根据网络分层的“黑盒”思想，TCP 协议仅使用网络层的服务，因此TCP 的拥塞控制机制独立于IP 层的内部工作状态。
答案与解析

答案：C

发送窗口的大小取接收方接收窗口和拥塞窗口的较小值，在同一时刻，发送方的发送窗口并不总是和接收方的接收窗口一样大，故A 错误。“拥塞避免”也并非指完全能够避免拥塞，而是指在拥塞避免阶段将cwnd 值控制为按线性规律增长，使网络比较不容易出现拥塞，故B 错误。TCP 的拥塞控制正是为了适应和响应IP 网络内部的拥塞状态（如路由器丢包）而设计的，两者密切相关，故D 错误。

第 38 题
一个TCP 连接总是以1KB 的最大段长发送TCP 报文段，发送方有足够多的数据要发送。当拥塞窗口cwnd 为16KB 时，发送方收到了3 个冗余的ACK，如果接下来的4 个RTT 时间内的TCP 段的传输都是成功的，那么当第4 个RTT 时间内发送的所有TCP段都得到肯定应答时，拥塞窗口大小是（ ）。
  1. A．10KB
  2. B．11KB
  3. C．12KB
  4. D．16KB
答案与解析

答案：C

当发送方收到3个冗余ACK时，会触发快速恢复算法。此时，慢开始阈值ssthresh 被设置为当前拥塞窗口cwnd 的一半，即ssthresh=16KB/2=8KB，同时拥塞窗口cwnd 也更新为新的ssthresh 值，即cwnd=8KB，并立即进入拥塞避免阶段。在拥塞避免阶段，每经过一个RTT，拥塞窗口大小增加一个MSS（1KB）。因此，经过4 个成功的RTT 后，拥塞窗口将从8KB 线性增长4 次，最终大小为8KB + 4 * 1KB = 12KB。

第 39 题
一个TCP 连接以MSS=1KB 发送数据段。某时刻cwnd=16KB, ssthresh 为12KB。此时发生超时事件。若RTT=10ms，则该连接至少需要经过多长时间，其拥塞窗口才能恢复到8KB？
  1. A．30ms
  2. B．40ms
  3. C．60ms
  4. D．70ms
答案与解析

答案：A

当发生超时事件时，无论之前的ssthresh 值是多少，新的ssthresh 都会被更新为当前cwnd的一半，即ssthresh=16KB/2=8KB ，而拥塞窗口cwnd则会重置为1个MSS ，即cwnd=1KB，并进入慢开始阶段。在慢开始阶段，拥塞窗口每经过一个RTT 就会翻倍。其增长过程为： 1KB -> 2KB (经过1 个RTT) -> 4KB (经过2 个RTT) -> 8KB (经过3 个RTT)。当cwnd 达到8KB 时，正好等于新的ssthresh 值，满足了题目要求。因此，所需的最短时间为3 个RTT，即3 * 10ms=30ms。

第 40 题
一个TCP 连接（MSS 为1KB）的ssthresh 初始值为32KB。在cwnd 增长至16KB 时，发生了超时，此后经过了7 个RTT，又收到了3 个冗余的ACK，则此时ssthresh 的值将会被置为多少？
  1. A．6KB
  2. B．8KB
  3. C．12KB
  4. D．16KB
答案与解析

答案：A

在cwnd=16KB 时发生超时，此时ssthresh 被更新为16KB/2=8KB，cwnd 重置为1KB。随后连接开始恢复，先经历3 个RTT 的慢开始（cwnd 从1->2->4->8），然后进入拥塞避免阶段。在接下来的7-3=4 个RTT 里，cwnd 从8KB 线性增长到12KB。此时，发生了第二次拥塞事件，即收到3 个冗余ACK。根据快速恢复规则，ssthresh 被设置为当前cwnd 的一半，即12KB/2=6KB。

第 41 题
若主机甲与主机乙已建立一条TCP 连接，最大段长（MSS）为1KB，往返时间RTT 为2ms，则在不出现拥塞的前提下，拥塞窗口从8KB 增长到32KB 所需的最短时间是（ ）。
  1. A．2ms
  2. B．4ms
  3. C．24ms
  4. D．48ms
答案与解析

答案：B

TCP 拥塞窗口最慢的增长方式是慢开始阶段的指数增长。初始拥塞窗口为8KB，目标为32KB，其指数增长过程为：经过第1个RTT 后，cwnd 从8KB增长到16KB；再经过第2 个RTT，cwnd 从16KB 增长到32KB，达到目标。整个过程共需要2 个RTT。由于给定的RTT 为2ms，因此所需的最短时间为2 RTT × 2 ms/RTT = 4ms。

第 42 题
假设主机甲和主机乙已建立一个TCP 连接，MSS=1KB，甲一直有数据向乙发送。当甲的拥塞窗口为16KB 时，收到了3 个冗余ACK，则甲的拥塞窗口再次增长到16KB 所需要的时间至少是（ ）。
  1. A．1RTT
  2. B．4RTT
  3. C．8RTT
  4. D．11RTT
答案与解析

答案：C

当在cwnd=16KB 时收到3个冗余ACK，TCP进入快速恢复阶段。慢开始阈值ssthresh 和拥塞窗口cwnd 都被设置为当前cwnd 的一半，即8KB，并立即进入拥塞避免算法。此时，拥塞窗口需要从8KB 恢复到16KB，需要增加8KB。在拥塞避免阶段，拥塞窗口每个RTT 增加1KB，因此总共需要8 个RTT 的时间。

第 43 题
一台主机使用TCP（MSS=1KB,RTT=50ms）传输数据，在cwnd 为16KB 时发生超时。此后，接收方在其所有ACK 中通告的rwnd 恒为14KB。请计算，从超时事件发生起到该主机的cwnd 再次增长到16KB，其平均数据吞吐量约为多少？
  1. A．75.5 KB/s
  2. B．152.5 KB/s
  3. C．178.2 KB/s
  4. D．227.5 KB/s
答案与解析

答案：C

超时事件后，慢开始门限ssthresh 变为当前cwnd 的一半，即16KB/2=8KB，拥塞窗口cwnd 重置为1KB，进入慢开始阶段。在慢开始阶段，cwnd 从1KB 开始按指数规律增长，直到达到ssthresh，进入拥塞避免阶段。过程为1KB→2KB→4KB→8KB，共经历3 个RTT，发送的数据量为1+2+4=7KB。在拥塞避免阶段，cwnd 从8KB 开始，每个RTT 增加1KB，直到增长到16KB。此过程需要16-8=8 个RTT。在此期间，发送窗口swnd=min(cwnd, rwnd)。因rwnd 恒为14KB，故各RTT 发送的数据量为min(8, 14)+min(9, 14)+...+min(15, 14) = 8+9+10+11+12+13+14+14 =91KB。总耗时为3+8=11 个RTT，即11*50ms= 550ms = 0.55s。总发送数据量为7KB+ 91KB = 98KB。因此，平均数据吞吐量为98KB/0.55s≈178.2 KB/s，故C 正确。

第 44 题
在一个启用了选择确认SACK 的TCP 连接中，发送方已发送了序号从1000 到8999 的字节流 （分为8 个1000 字节的段）。随后，发送方收到了一个来自接收方的TCP 段，其首部中ack 字段值为3000，且SACK 选项中包含一个块(left edge=5000, right edge=7000)。根据这些信息，发送方可以推断出接收方当前确实丢失了哪些序号范围的数据?
