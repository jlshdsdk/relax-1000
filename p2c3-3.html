第 63 题
关于Cache 写策略，若采用回写法，以下说法正确的是（ ）。
  1. A．数据写入Cache 的同时也写入主存
  2. B．只有当Cache 中的数据被替换时，才将其写回主存
  3. C．写操作速度较慢，因为需要等待主存写入完成
  4. D．不会出现Cache 与主存数据不一致的情况
答案与解析

答案：B

回写法中，数据写入Cache后不立即写入主存，只有当该数据所在的Cache块被替换时，才将其写回主存，写操作速度快，因为不需要每次都等待主存写入完成，但会存在Cache与主存数据不一致的时间段；数据写入Cache同时写入主存的是全写法；C描述的也是全写法的特点；写回法会出现数据不一致情况，A、C、D错误。

第 66 题
假定页表有一个控制位C，用来表示对应页⾯是否可在Cache 缓存。C=1 表示可在Cache 缓存， C=0 表示不可在Cache 缓存。以下关于虚实地址转换时对C 进行相关处理的描述，其中错误的是（ ）。
  1. A．若装入位为0，则无需考虑C 的取值如何
  2. B．若修改位为1，则不管C 原来的值如何都将其清0
  3. C．若C=0，则根据转换后的地址直接访问主存而不访问Cache
  4. D．若C=1，则根据转换后的地址先到Cache 中进行访问
答案与解析

答案：B

装入位为0表示不在主存中，故也一定不在Cache中，无需考虑，A正确。 C=0表示一定不在Cache，故无需访问Cache，C正确。C=1表示可能在Cache中，故要先在Cache中查找，D正确。B选项一个页面被写入数据（修改位变1），是非常正常的内存访问行为，这绝不会改变该页面的物理存储属性。普通的RAM页面被写了之后，依然是RAM，依然允许被Cache缓存，根本不存在“将其清0（变成不可缓存）”的逻辑。B错误。

第 67 题
假定编译器将赋值语句“x = x + 3;” 转换为机器指令“add [xaddr], 3”，其中xaddr 是变量x 对应的存储单元虚拟地址。若执行该指令的计算机采用页式虚拟存储管理方式，并配有相应的TLB 。该计算机的Cache 采用回写（Write-Back）和写分配（Write-Allocate）策略。在执行该指令的过程中：取指阶段TLB 和Cache 均命中；读操作数阶段，TLB 命中但Cache 未命中，且此时需要替换一个脏行（脏位为1）；写回结果阶段Cache 命中。则执行完该指令全过程，完成其功能需要访问主存的次数是 （）。
  1. A． 1 次
  2. B． 2 次
  3. C． 3 次
  4. D． 4 次
答案与解析

答案：B

取指令阶段（0次访存）：题干明确指出取指阶段TLB和Cache均命中，直接从Cache中拿到指令，访问主存0次。读操作数阶段（2次访存）：指令add [xaddr], 3是典型的“读-改-写”指令，必须先将x从内存中读出来。TLB命中，MMU直接将虚拟地址xaddr翻译为物理地址，不需要访问主存中的页表。物理地址送往Cache，此时Cache未命中。关键点（脏行写回），因为Cache采用回写策略，且未命中时触发了替换，而被替换的Cache行是“脏行”（脏位为1，说明里面的数据被修改过且尚未同步到主存），此时硬件必须先将该脏行的数据写回主存（第1次访问主存）。关键点（新块调入），脏行腾空后，由于是读失效，需要将包含变量x的主存块读入Cache（第2次访问主存）。随后CPU从Cache中读取x的值参与加法运算。写回结果阶段（0次访存）：运算完成后，新值需要写回xaddr，此时包含x的数据块刚刚在读阶段被调入Cache，因此写回时Cache必然命中。在回写策略下，Cache命中时仅修改Cache行中的内容，并将脏位置为1，不需要同步写入主存。因此这一阶段访问主存0次。总结：0（取指）+ 2（读操作数）+ 0（写回）= 2次。

第 69 题
已知某计算机按字节编址，虚拟地址为32 位，物理地址为28 位，采用单级页式虚拟存储管理，页面大小为4KB。其数据Cache 采用4 路组相联映射，总容量为16KB，主存块大小为32B。若某进程执行时，CPU 发出虚拟地址0x00456ABC，查页表后得到的对应物理页框号为0x012F。则该主存块被映射到的Cache 组号（十进制）以及Cache 标记（Tag，十六进制）分别是（ ）。
  1. A． 组号85，标记0x012F
  2. B． 组号85，标记0x0456
  3. C． 组号43，标记0x012F
  4. D． 组号43，标记0x0456
答案与解析

答案：A

第一步，明确地址划分：主存物理地址共28位。Cache块大小为32B，因此块内偏移占5位。Cache总容量16KB，4路组相联，共有16KB / (4 * 32B) = 128组，因此组索引占7位。物理地址高处的28 - 5 - 7 = 16位即为Cache标记(Tag)。第二步，拼装物理地址：页面大小为4KB，因此虚拟地址和物理地址的低12位（页内偏移）完全相同。虚拟地址0x00456ABC的低12位为0xABC。物理地址由物理页号和页内偏移拼接而成，即物理地址= 0x012FABC。第三步，提取组号和标记：组索引位(7 位) +块内偏移位(5 位) = 12 位=页内偏移位数。这意味着Cache的组号完全由页内偏移决定，不受虚拟/物理页号影响。将低12位的0xABC转为二进制： 1010 1011 1100。抛弃最低的5位（1 1100），接下来的7位即为组索引：101 0101，转化为十进制为85。Cache标记为物理地址去掉低12位后的高16位，即0x012F

第 70 题
关于内存管理单元(MMU) 的工作机制及异常处理，下列说法正确的是（ ）。
  1. A． 缺页时，MMU 会直接从外存中读取目标页面并调入主存
  2. B． Cache 缺失和TLB 缺失一样，都是在MMU 进行地址转换的过程中被检测出来的
  3. C． 若TLB 命中，MMU 在完成虚拟地址到物理地址的转换时，完全不需要访问页表基址寄存器 (PTBR)
  4. D． 无论是哪种计算机架构，TLB 缺失后的表项填充操作都必须由操作系统内核中的异常处理程序 （软件）来完成
答案与解析

答案：C

A选项错误：MMU只能检测缺页并触发缺页异常中断，真正的缺页处理程序是由操作系统（软件）在内核态接管并负责从外存读取页面调入主存的，并非硬件直接读取。 B选项错误：MMU负责将虚拟地址转化为物理地址，在此过程中会检测越权、缺页和TLB缺失。Cache缺失是在MMU完成翻译输出物理地址之后，CPU访问主存数据时检测的，不属于MMU的工作范畴。 C选项正确：PTBR是MMU访问内存页表的入口指针。当TLB命中时，MMU直接从TLB中获取物理页号并拼接页内偏移生成物理地址，整个过程完全绕过了PTBR和主存中的页表。 D选项错误：TLB缺失的处理机制因架构而异。例如在x86或ARM架构中，硬件内部自动遍历内存填入TLB（纯硬件完成）；而在MIPS架构下，才需要触发异常由OS软件手动填入。

第 71 题
某系统依次进行4 次访存操作的情况如下：
①TLB 命中，Cache 未命中②TLB 未命中，页表未命中，cache 未命中
③TLB 命中，Cache 命中④TLB 未命中，页表命中，Cache 未命中已知缺页处理时会更新TLB 和页表，将缺页处理过程只视作一次访存，4 次访存操作之间操作数独立，则总访存次数是（）。
  1. A．6
  2. B．5
  3. C．8
  4. D．7
答案与解析

答案：A

操作I：TLB命中→物理地址，Cache未命中→1次访存。操作II：TLB未命中访问页表（1次访存）→缺页处理（视作1次访存）→重新执行→TLB命中→物理地址，Cache未命中（1次访存）。操作II共1 + 1 + 1 = 3次。操作III：TLB命中→物理地址，Cache命中→0次访存。操作IV：TLB未命中→查页表命中→物理地址，Cache未命中→2次访存。总计：1 + 3 + 0 + 2 = 6次，A正确。

第 73 题
已知某计算机采用单级页式虚拟存储管理，配有TLB 和Cache。CPU 执行一条读内存的取数指令（不考虑取指阶段）。假设不考虑Cache 的写回操作（Write-Back）造成的额外开销，并且注意cache 也会缓存页表项。下列关于访存状态组合与主存访问次数的推断中，错误的是（ ）。
  1. A． 若本次取数操作完全没有访问主存（即0 次主存访问），则必定是因为：TLB 命中，且目标数据在Cache 中命中
  2. B． 若TLB 未命中，但本次取数操作仅访问了1 次主存，可能是因为：页表项在Cache 中未命中，而目标数据在Cache 中命中
  3. C． 若TLB 命中，但目标数据在Cache 中未命中，硬件可能仅需访问1 次主存可完成该取数指令
  4. D． 无论Cache 的命中率多高，只要在地址翻译阶段检测到了缺页异常，则本次访存的TLB 必定是未命中的，且目标数据必定不在Cache 中
答案与解析

答案：A

A错误：很多人认为0次主存访问的唯一条件就是“TLB命中+ Cache命中”。但实际上，如果发生以下情况：TLB未命中→MMU 去查页表→页表项在Cache中命中→获取物理地址后，目标数据在Cache中也命中。在这个“TLB 缺失，但双Cache命中”的过程中，数据全是从高速缓存中读取的，主存访问次数依然是0次。因此0次主存访问不能说明TLB命中。 B正确：这是非常典型的一种状态组合。TLB未命中，硬件去查页表；此时页表项（PTE）在Cache中未命中，被迫访问1次主存将页表块读入Cache；拿到物理地址后去查目标数据，目标数据此时幸运地在Cache中命中。整个过程加起来，刚好只访问了1次主存。 C正确：这也是极其常规的缓存未命中情况。TLB命中，直接拿到物理地址（0次主存访问）。拿着物理地址去查Cache，发现数据未命中，于是硬件去主存中取数据块放入Cache（访问1次主存）。总耗时就是1次主存访问的开销。 D正确：如果发生缺页，说明该页面根本不在主存中。既然不在主存中，TLB作为一个只缓存 “有效物理映射”的快表，里面绝对不可能有它的有效表项，所以TLB必然未命中。同理，Cache缓存的是主存的子集。既然老大哥（主存）里都没有这块数据，小弟（Cache）里自然不可能有。所以目标数据必然不在Cache中。该推断完全正确。

第 75 题
为了缓解处理器与主存之间的速度差异，现代计算机系统同时引入了TLB 和Cache。下列关于TLB 与Cache 工作机制及缺失行为的叙述中，错误的是（ ）。
  1. A． 进程切换时，由于虚拟地址空间发生改变，TLB 必须进行刷新而Cache 通常无需刷新，因为不同进程的Cache 内容可以共存
  2. B． CPU 发出内存访问请求时，TLB 加速的是“地址翻译”，以虚拟页号作为查询依据；Cache 加速的是“数据读取”，通常以物理地址作为查询依据
  3. C． 当Cache 发生缺失时，必然由硬件自动完成数据块的替换与调入；而当TLB 发生缺失时，必然会触发TLB 缺失异常，引出操作系统内核中的异常处理程序来手动填充表项
  4. D． 在一次取数操作中，完全可能出现“TLB 缺失，但由于页表项和目标数据均在Cache 中命中，最终硬件访问主存的次数为0 次”的理想情况
答案与解析

答案：C

Cache 和TLB 对比如下A正确：Cache的查询Key是物理地址，而物理地址在内存中是全局唯一的，因此进程切换时无需刷新Cache。但是，TLB的查询Key是虚拟地址，不同进程中相同的虚拟地址会映射到完全不同的物理地址上。如果不刷新TLB，新进程就会错误地使用旧进程的地址翻译结果。 B正确：这一项对比了二者的定位与寻址方式。TLB的核心目的是解决“每次地址翻译都要访问主存页表的开销”，它的查询Key是虚拟页号，输出结果是物理页号。而Cache的核心目的是解决 “CPU与主存速度差”，它的缓存对象是主存中的数据或指令块，查询Key则是物理地址。简单来说：TLB加速“找地址”，Cache加速“取数据”。 C错误：Cache缺失确实对软件完全透明，永远由硬件自动处理并从下级存储取数据块填入Cache。但TLB缺失的处理方式视计算机架构而定：
①x86 或ARM 等架构中，TLB 是由硬件管理的，MMU 的内部硬件会自动遍历内存页表并填入TLB，无需操作系统介入。
②MIPS等软件管理TLB 的架构中，TLB缺失才会触发异常，由操作系统的处理程序填入。 D正确：这一项考查了命中的组合情况。TLB缺失仅仅意味着“快表里没有缓存这个映射”，但只要该页面有效（未发生缺页），数据就存在于主存中，也就有可能被缓存到了Cache中。当TLB缺失时，硬件会去查页表。如果代表该映射关系的页表项刚好在Cache中命中，且翻译出物理地址后，目标数据也刚好在Cache中命中，那么整个取数过程的数据全部是从Cache这个高速器件里拿到的，实际去读写主存（DRAM）的次数依然为0次。

第 76 题
段式虚拟存储器的基本原理是（ ）。
  1. A．将程序按逻辑模块分段，每段分配连续的内存空间
  2. B．将内存划分为固定大小的页，程序按页存储
  3. C．结合页式和段式的优点，先分段再分页
  4. D．所有程序共享一个段表，通过段号访问
答案与解析

答案：A

段式虚拟存储器将程序按逻辑模块（如代码段、数据段等）分段，每段在内存中分配连续的空间，通过段表进行地址映射，A正确；B描述的是页式虚拟存储器；C是段页式虚拟存储器；每个进程都有自己的段表，不是共享一个段表，B、C、D错误。

第 77 题
某进程的段表内容如下所示访问并修改<段号：段内地址>=<082H: 130H>的逻辑地址的数据时，进行地址转换的结果是 （）。
  1. A．段缺失异常
  2. B．越权异常
  3. C．越界异常
  4. D．得到内存地址2304
答案与解析

答案：C

082H 转成10 进制是130，此时查段表，存在位是1，段长是304，而此时段内地址为130H，转成十进制为256*1+3 * 16 = 304，段内地址从0 开始的，304 是第305 号单元，305>304 发生越界异常。思考：若把段内地址130H 改为12FH，答案是什么？（越权）总结： • 要分清十进制和16 进制，页表和段表中的页号和段号往往是连续排列，所以是十进制，题目中可能会给16 进制，要注意转换，进制统一后，需要考虑段（页）表长度，看段（页）号是否超出段表长度，超出发生越界异常。 • 确定好段（页）表项，看存在位是1 还是0，若是0，可知段（页）不在内存，发生段缺失异常。 • 若是段式，需要考虑段长，同样需要考虑16 进制和10 进制的转换，以及下标问题。举例：若段长为100，那么段内地址是0-99，100 即发生越界异常。以上都正常，最后还需要查看权限信息，本题中访问并修改，那么涉及写读和写权限，只读权 • 限的话会发生越权异常。

第 79 题
某段页式虚拟存储器系统中，段表项大小为4 字节，页表项大小也为4 字节。若某进程的段表中有8 个段表项，平均每个段的页表有32 个页表项，则该进程的段表和页表共占用内存空间大小是 （）。
  1. A．512 字节
  2. B．1024 字节
  3. C．1056 字节
  4. D．2048 字节
答案与解析

答案：C

段表占用空间=段表项数量×段表项大小= 8×4 = 32字节；页表占用空间= 段表项数量×平均每个段的页表项数量×页表项大小= 8×32×4 = 1024字节；段表和页表共占用空间 = 32 + 1024 = 1056字节，C正确。
